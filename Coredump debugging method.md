# What is coredump?
The program exits or terminates abnormally during operation due to various exceptions or bugs, and a file called core is generated under certain conditions.

Usually, the core file contains the memory, register status, stack pointer, memory management information, and various function call stack information when the program is running.

We can understand it as a file generated by storing the current state of the program. Many programs will generate a core file when they fail. By analyzing this file with tools, we can locate the corresponding stack call information when the program exits abnormally, find out the problem and solve it in time.

# Usage
Open system core tracing through ulimit command

The ulimit -c parameter can specify the size of the core stack area for debugging. We can directly specify the maximum limit of the record by entering
ulimit -c unlimited

Set the path for saving coredump

The path for generating coredump is specified by the kernel variable /sys/proc/kernel/core_pattern. The default address is core.

Note that this address means the default relative path file core when running the program.

However, due to the characteristics of the product, this path is usually read-only. Therefore, we must modify it to a writable path.

Since the coredump file may be large, there must be enough storage space on the path (you can use the NFS we mentioned earlier or
TF card to store the coredump file). In addition, the path supports wildcards. Regarding wildcard expressions, I will not go into details here.

echo "/tmp/nfs/%e-%p-%t.coredmp" > /proc/sys/kernel/core_pattern

Run the code. If an error occurs, a core file will be generated

View the error through GDB
``` gdb [program name] [xxx.coredmp] ```
